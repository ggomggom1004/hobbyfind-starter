# HobbyFind 유스케이스 문서

## 1. 서비스 개요
- 서비스명: HobbyFind
- 서비스 유형: 웹서비스
- 목적: 사용자가 운동형, 지능형, 예술형 카테고리의 취미를 탐색하도록 돕는다.
- 이용 조건: 로그인 없이 이용 가능

## 2. 액터 정의
- 사용자: 웹사이트에 방문하여 취미를 확인하고 카테고리를 선택하는 사람
- 시스템: 사용자의 요청에 따라 취미 목록과 페이지를 표시하는 웹서비스

## 3. 주요 유스케이스
### UC-01 메인 페이지 탐색
- 사전조건: 사용자가 웹브라우저에 접속할 수 있다.
- 실행 흐름:
  1. 사용자가 HobbyFind 메인 페이지에 접속한다.
  2. 시스템이 서비스 소개 영역을 표시한다.
  3. 시스템이 전체 취미 18개의 카드를 표시한다.
  4. 사용자가 취미 목록을 탐색한다.
- 사후조건: 사용자가 전체 취미를 확인한다.

### UC-02 카테고리별 페이지 이동
- 사전조건: 사용자가 메인 또는 카테고리 페이지에 접속한 상태다.
- 실행 흐름:
  1. 사용자가 상단 메뉴에서 운동형, 지능형, 예술형 중 하나를 선택한다.
  2. 시스템이 해당 카테고리 전용 페이지로 이동한다.
  3. 시스템이 선택된 카테고리명과 소개 문구를 표시한다.
  4. 시스템이 해당 카테고리 취미 6개를 표시한다.
- 사후조건: 사용자가 선택한 카테고리의 취미 목록을 확인한다.

### UC-03 메인 페이지 필터 이용
- 사전조건: 메인 페이지가 정상적으로 표시되어 있다.
- 실행 흐름:
  1. 사용자가 카테고리 필터를 선택한다.
  2. 시스템이 선택된 카테고리의 취미 카드만 표시한다.
  3. 사용자가 전체 필터를 선택하면 18개 취미가 다시 표시된다.
- 사후조건: 필터 선택 결과가 화면에 반영된다.

## 4. 대체 흐름 및 엣지 케이스
- 사용자가 로고를 클릭하면 메인 페이지로 돌아간다.
- 이미 선택된 카테고리를 다시 클릭해도 정상적으로 페이지가 표시된다.
- 해당 카테고리 데이터가 비어 있다면 빈 목록 안내 메시지를 표시한다.
- 존재하지 않는 주소로 접근하면 찾을 수 없는 페이지를 표시한다.

## 5. 주요 단계 및 이벤트 흐름
- 방문: 메인 페이지 접속 → 전체 취미 표시
- 선택: 카테고리 메뉴 클릭 → 전용 페이지 이동
- 필터: 필터 선택 → 표시할 카드 변경
- 복귀: 로고 클릭 → 메인 페이지 이동

## 6. 비즈니스 규칙 및 제약사항
- 취미 목록은 운동형, 지능형, 예술형 각각 6개, 총 18개로 고정한다.
- 회원가입 및 로그인 없이 이용할 수 있다.
- 카테고리별 페이지는 해당 분야의 취미만 표시한다.
- 결제, 예약, 댓글 기능은 구현하지 않는다.

## 7. 예외 처리 절차
- 취미 데이터가 없을 경우 빈 상태 안내 메시지를 보여준다.
- 이미지 로딩에 실패할 경우 대체 이미지 또는 기본 표시 영역을 사용한다.
- 잘못된 경로로 접근할 경우 404 안내 페이지를 표시한다.
- 화면이 정상적으로 표시되지 않을 경우 새로고침으로 다시 접근할 수 있다.

## 8. UI 고려사항
- 카드의 크기, 간격, 정렬을 일관되게 유지한다.
- 선택된 메뉴 및 필터를 시각적으로 구분한다.
- 버튼과 메뉴에 마우스를 올리면 반응이 나타나도록 한다.
- 모바일과 데스크톱 화면에서 이용할 수 있도록 반응형으로 구현한다.
- 글자 크기와 명도 대비를 고려하여 읽기 편하게 구성한다.

## 9. 데이터 요구사항 및 데이터 흐름
- 각 취미는 이름, 카테고리, 소개 문구, 이미지 경로를 가진다.
- 정적 데이터에 전체 취미 18개를 저장한다.
- 사용자가 카테고리를 선택하면 해당 카테고리에 속한 취미 목록을 추출하여 표시한다.
- 서버 데이터베이스나 사용자 계정 정보는 필요하지 않다.

## 10. 보안 및 개인정보 고려사항
- 로그인 및 개인정보 수집 기능을 구현하지 않는다.
- 사용자가 직접 입력하는 개인정보는 저장하지 않는다.
- 외부 이미지나 패키지를 사용할 경우 신뢰할 수 있는 출처를 활용한다.
- 필요한 기능만 구현하고 불필요한 외부 서비스 연동은 하지 않는다.
